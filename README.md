# 解说剧分镜工坊

一个面向小说解说剧生产的本地网页工具。它把小说正文拆解为可编辑的分镜表，并为每个镜头生成通用中文画面提示词。

当前版本是 v1 原型：单人本地使用，不做账号系统，不做云端数据库，不要求登录。

## 功能

- 选择视觉风格：`2D`、`3D`、`3D高精度CG`、`仿真人`，并提供常驻“视觉描述”输入框，可直接填写更明确的自定义风格
- 选择网文解说剧本风格：爽文、悬疑、言情、玄幻、都市、惊悚，也可以输入自定义剧本风格
- 选择语言：中文或英文
- 设置阅读速率，默认 `0.95 秒/字`
- 设置目标分集数，生成后在分镜表和导出文件中标记分集
- 支持一次导入多个 `.txt` 文件，每个文件作为独立本地项目/单集进入队列，可逐个载入处理
- 本地历史记录保存在 IndexedDB，可查看、切换、删除旧项目，并从历史记录重新打开继续处理
- 分镜表和 CSV/Excel 导出的镜头编号按每集重新从 1 开始，JSON 仍保留全片全局 `index`
- 在页面内临时配置模型、API Key 和 Base URL，方便本地测试不同 API
- 应用 API 配置后自动读取当前可用模型，并支持手动刷新模型列表
- API 配置会保存在当前浏览器本地存储，刷新后自动恢复并重新连通后端
- 创作前会检查 API 连通状态，开始后显示当前理解/分镜生成阶段
- 英文输入会自动生成中文译文，方便对照查看
- 粘贴长英文或中文文本时会自动识别语言，并同步切换阅读单位，减少长文误用中文统计口径
- 输入整本小说，生成前展示字数、句数、预计分段和阅读总时长
- 独立理解阶段：提取人物、场景、关键事件、情绪节奏和连续性提示；长文会先分段理解，再分批合并理解档案
- 理解档案面板默认压缩为内部滚动区域，长档案可以展开查看，避免撑开整个工作台
- 分镜生成阶段：先按约 `2200` 字的小段拆分，再并发生成分镜，降低上下文过长导致的漂移风险
- 分镜阶段会再次拆成更短的“分镜单元”，避免单个镜头旁白过长，适配视频生成长度限制
- 英文分镜单元会自动重平衡过短尾句，避免把句末单词单独拆成一个镜头
- 英文直接引语会作为硬边界处理，避免上一句尾词和下一句对白粘连
- 英文长对白即使被拆成多个分镜单元，每个片段也会保留引号形态，便于模型继承说话人并识别为对白
- 分镜表中的秒数表示镜头画面时长，不再等同于旁白阅读时长
- 人物、动作、视角或场景切换时，提示词会要求补齐第三方反应镜头或场景空镜，增强镜头之间的连贯性
- 引号内的直接发言会优先识别为角色对白，即使原文没有明确写说话人，也不会降级成旁白
- 长文生成改为分段流式返回：理解阶段显示进度，分镜阶段每完成一段就把该段镜头追加到表格，不再等整本全部完成
- 生成中可以取消，已生成的分镜会保留并进入本地自动保存
- 理解阶段遇到连接错误或临时失败后，页面会保留当前文本和设置，并提供“重新尝试理解”入口，不需要手动刷新或重新粘贴正文
- 分镜阶段遇到 `503 system cpu overloaded`、`Connection error` 等临时失败后，页面会保留已完成分段，并在错误栏和状态栏明确提示可从失败段“继续重试”，不需要重跑理解阶段和已成功分镜段
- 提示词按镜头制作格式输出：时间段、镜头语法、画面细节、摄影机状态、声音设计、台词/旁白、导演批注；镜头语法支持景别切换、焦距变化和焦点转移，人物描写会补齐动作表情要素；提示词主体为中文，台词/旁白引用内容保留原文语言
- 提示词生成增加安全画面化规则：敏感或高风险情节会在画面、镜头、声音和导演批注中改为非露骨影视表达；旁白和对白阅读内容必须保留原文，不做任何改写
- 分镜表内编辑：旁白、落点句、画面描述、镜头类型、角色、场景、情绪、提示词
- 分镜表将提示词独立展示为导演工作台，主字段行会同步拉伸高度，便于长内容校对
- 本地 IndexedDB 自动保存项目状态
- 导出 `CSV`、`Excel` 和 `JSON`；从 `.txt` 导入的项目会按原文件名导出同名 Excel，例如 `ep01.txt` -> `ep01.xls`
- 历史记录中已生成分镜的项目支持单独导出 Excel，也支持一键导出全部已完成项目的同名 Excel
- 导出时提示词列会按镜头标签保留单元格内换行，便于复制到视频生成工具

## 技术栈

- Frontend: Vite + React + TypeScript
- Backend: Node.js + Express
- AI: OpenAI Responses API + Structured Outputs
- Local storage: IndexedDB
- UI icons: lucide-react

## OpenAI 配置

如果只是查看界面，不需要配置 API Key。

如果要真实生成理解档案和分镜，需要在项目根目录创建 `.env`：

```bash
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.4
OPENAI_BASE_URL=
PORT=8787
```

可参考 `.env.example`。

说明：

- API Key 只在后端读取，不会进入前端 bundle。
- 默认模型是 `gpt-5.4`。
- 如果当前账号无法使用该模型，后端会返回明确错误。可以通过 `OPENAI_MODEL` 改成可用模型。
- 页面中的 API 配置会覆盖当前运行中的本地后端配置，并保存在当前浏览器本地存储；不会写入 `.env`。
- 如果使用第三方模型网关，`OPENAI_BASE_URL` 或页面里的 Base URL 必须填写 OpenAI-compatible API 根地址，通常以 `/v1` 结尾；不要填写网关控制台首页，否则后端会收到 HTML 页面而不是 JSON API 响应。
- 如果网关返回 `502 Upstream request failed`、`invalid character ... looking for beginning of value` 或其他非 JSON 响应，通常表示第三方网关或上游模型临时返回异常；系统会自动重试一次，持续出现时可降低并发或切换模型。
- 如果网关返回 `503 system cpu overloaded`，通常表示上游模型服务临时过载；系统会按指数退避自动重试，仍失败时建议把分段并发降到 `1`、稍后重试或切换可用模型。
- 如果网关返回 `Connection error`、`network error`、`ECONNRESET`、`ECONNREFUSED` 等连接错误，系统会按临时错误处理并进入指数退避重试；理解阶段仍失败时可在页面直接重新尝试理解，分镜阶段仍失败时可用“继续重试”从失败段续跑。
- 所有 Responses 请求都会携带 `instructions` 字段，以兼容要求 `Instructions are required` 的第三方网关。
- 所有 Responses 请求的 `input` 都使用消息数组打包，以兼容要求 `Input must be a list` 的第三方网关。
- 如果第三方网关的 Responses API 兼容不完整，后端会自动回退到 Chat Completions JSON Schema；如果 JSON Schema 也不兼容，会再回退到普通 Chat Completions 并手动解析 JSON。
- 后端错误处理有本地 mock 测试覆盖，确保非 JSON 网关错误不会被误报为模型无权限，并避免真实模型不存在时触发无效回退。
- 分段并发数量可通过 `PARALLEL_CHUNK_LIMIT` 配置，默认 `2`，非法配置时兜底为 `2`，最大限制为 `6`。第三方网关不稳定时建议保持 `1-2`。
- 临时网关错误重试次数可通过 `TRANSIENT_REQUEST_RETRIES` 配置，默认 `3`，最大限制为 `6`；退避基础间隔可通过 `TRANSIENT_RETRY_BASE_DELAY_MS` 配置，默认 `1000` 毫秒。
- 分镜单次模型请求超时可通过 `MODEL_REQUEST_TIMEOUT_MS` 配置，默认 `90000` 毫秒；超时会按临时错误重试，分镜阶段还会尝试自动拆小段继续生成。
- 理解阶段请求超时可通过 `ANALYSIS_REQUEST_TIMEOUT_MS` 配置，默认 `180000` 毫秒。理解合并不再调用模型，而是在本地确定性去重、截断和合并，避免长篇合并阶段卡死或超时。
- 分镜段自动拆分重试深度可通过 `MAX_STORYBOARD_ADAPTIVE_SPLIT_DEPTH` 配置，默认 `2`，最大 `4`。当某个分镜段因 503、超时、非 JSON 等临时错误失败时，后端会把该段按 `【分镜单元】` 拆成更小子段重试，降低长段卡死和整段失败概率。
- 本地稳定性排查可启用 `JSSTORY_MOCK_AI=1`，它会绕过真实模型并返回 mock 结构化结果；配合 `JSSTORY_MOCK_STORYBOARD_FAIL_UNIT_LIMIT` 可以模拟大分镜段返回 `503 system cpu overloaded`，用于验证自动拆分重试和流式事件是否正常。
- 生成中前端会显示本地运行时长和“距离上次后端事件”的秒数；后端流连接建立后会发送 `heartbeat` 事件，用于区分页面无反馈、网络断开和模型/网关仍在处理。
- 分镜阶段输入会拆成 `【分镜单元】`，短句会尽量与相邻句合并，每个单元尽量对应一个镜头，单镜头旁白朗读估算不超过 `8` 秒。
- `durationSeconds` 表示镜头画面时长，用于视频生成和剪辑节奏；页面阅读速率只用于正文总时长估算，不直接决定分镜单元和镜头秒数。
- 每个分镜请求最多允许模型输出 16 个镜头，优先保证短镜头和动作连续性，而不是把多句旁白合并成长镜头。
- 理解结果合并会按每批 4 段递归合并，避免长文在合并阶段重新形成超长上下文。

## 使用流程

1. 在顶部确认 API 配置，默认会沿用本地 `.env` 或当前环境变量中的 API。
2. 点击“应用配置”后，系统会读取当前 API Key 和 Base URL 可用的模型列表。
3. 选择视觉风格、剧本风格、语言、阅读速率和目标分集数；需要更精确画面风格时，可直接编辑“视觉描述”。
4. 在小说正文区域粘贴文本；如果语言是英文，系统会自动生成中文译文。
5. 检查系统估算的阅读单位、句数、预计分段和总时长。
6. 点击“生成分镜与提示词”。
7. 点击后系统会立即显示状态：先执行理解阶段，再并发执行分段分镜阶段。
8. 在分镜表中按分集人工校对和编辑。
9. 导出 CSV、Excel 或 JSON。

## API

### `GET /api/config`

返回当前后端模型和 API Key 配置状态。

### `POST /api/config`

临时更新当前运行中的本地后端配置：

- `model`
- `apiKey`
- `baseURL`

### `GET /api/models`

返回当前 API Key 和 Base URL 下可读取到的模型 ID 列表。

### `POST /api/translate`

输入英文正文，返回中文译文，用于英文模式下的本地对照查看。

### `POST /api/analyze`

输入小说正文和参数，返回理解档案：

- 故事钩子
- 人物设定
- 场景清单
- 关键事件
- 情绪节奏
- 连续性提示

### `POST /api/storyboard`

输入小说正文、参数和理解档案，返回分镜结果：

- 镜头编号
- 分集编号
- 原文句组
- 落点句
- 旁白
- 角色对白
- 画面描述
- 镜头类型
- 角色
- 场景
- 情绪
- 通用中文提示词
- 镜头画面时长

### `POST /api/generate/stream`

输入小说正文和参数，返回 `application/x-ndjson` 流式事件。当前是分段级流式，不是 token 级流式：结构化模型调用仍然需要等单段 JSON 完成后才能解析，但前端会在每段分镜完成时立即追加显示。
分镜流式过程中的分集编号是临时显示，`done` 事件会返回最终重排后的完整 `shots`，前端会自动替换，保证完成后的表格和导出文件分集编号一致。

事件包括：

- `heartbeat`
- `started`
- `analysis_started`
- `analysis_chunk`
- `analysis_merge`
- `analysis_merge_progress`
- `analysis_completed`
- `storyboard_started`
- `storyboard_progress`
- `storyboard_chunk`
- `done`
- `error`

客户端取消或断开连接后，后端会停止继续派发新的分段请求，并向 OpenAI SDK 请求传递取消信号，尽量减少取消后继续消耗 API 的情况。

### `POST /api/generate/storyboard/resume`

用于分镜阶段失败后的手动续跑。前端会传入原文、设置、已完成的理解档案、已生成镜头和失败分段索引；后端只从失败分段继续生成剩余分镜，并继续通过 NDJSON 返回：

- `storyboard_started`
- `storyboard_chunk`
- `done`
- `error`

续跑接口会保留已有镜头，完成后重新分配最终分集编号。为了提高 503 过载后的成功率，续跑阶段按剩余分段串行处理。

## 提示词格式

分镜的 `prompt` 字段会按固定镜头格式生成：

```text
[00:00-00:00s]
[镜头语法 / 视角 / 景别 / 焦距 / 焦点变化 // 运动或强度]
[画面细节] 主体、动作、空间、表情、构图、光线、色彩、关键道具、视觉风格；人物全身/半身描写会包含表情细节、手部动作、身体姿态、视线方向；面部/近景/特写描写会包含嘴角状态、眼部状态、面部状态、视线方向；如果是主观视角，会明确是谁的视角。
[摄影机补充状态] 机位高度、运动方式、稳定程度、推拉摇移、景深、畸变或遮挡；需要时写清楚焦距变化、焦点转移和跟焦节奏。
[声音设计] BGM、环境声、拟音、情绪推进、音量或节奏变化。
[台词/旁白] 旁白：“对应原文内容”；角色名（情绪+发声方式）：“对应原文内容”。没有明确说话人时写：未指明说话者（情绪+发声方式）：“对应原文内容”。没有旁白或对话时写：无。
[导演批注] 镜头的戏剧目的、观众感受、剪辑或同框重点。
```

提示词主体必须使用中文，包括镜头语法、画面细节、摄影机补充状态、声音设计和导演批注。

默认镜头保持单一景别、单一焦距和稳定焦点；只有同一分镜单元确实存在情绪推进、动作结果、视线转移、信息揭示或叙事落点变化时，`[镜头语法]` 才表达为类似 `中景 -> 近景`，并说明切换原因、焦距变化和焦点转移。视觉风格加入审美指引：高级动画感，不是越真实越好，而是把真实的空间、光影和材质，控制在一个更有审美的动画世界里；该指引不改变安全画面化和对白/旁白边界规则。

旁白和所有角色对话都必须使用中文双引号；双引号里的内容保持原文语言，不翻译。英文小说的旁白/对白仍写英文，中文小说的旁白/对白仍写中文。原文中被中文或英文引号包裹的直接发言必须作为角色对白输出，不能混入旁白；确实无法判断说话人时使用 `未指明说话者`。没有旁白或对话时，`[台词/旁白]` 行写 `无`。

如果同一个镜头的 `[台词/旁白]` 行同时包含旁白和角色对白，两段阅读之间必须插入停顿标记。角色对白切到旁白时使用 `【停顿0.4s，角色名静默无发声】`，例如：`角色名（紧张+低声）：“原文对白”；【停顿0.4s，角色名静默无发声】；旁白：“原文旁白”`。旁白切到角色对白时使用普通 `【停顿0.4s】`。停顿标记不能放进双引号里，不能改变阅读原文；画面上应在停顿处切到闭口反应、旁观者、手部动作或环境物件，避免角色说完台词后继续张嘴承接旁白造成穿帮。

英文完整引号对白会先作为完整句识别；如果因为长度需要拆成多个分镜单元，每个片段也会重新包上引号，避免变成无引号旁白碎片。模型规则要求这些拆分片段继续作为 `dialogueLines` 输出，并从上下文、相邻对白片段和理解档案继承同一说话人。

视频生成相关字段会执行安全画面化处理。`sourceText`、`narration` 和 `dialogueLines.text` 保留原文，方便校对；`imageDescription`、`shotType`、`emotion` 和 `prompt` 的画面/镜头/声音/导演批注行会避免露骨血腥、伤害过程、身体细节、违法操作步骤、性化未成年人、仇恨羞辱等内容，并改写为远景、遮挡、剪影、声画错位、道具倒落、环境变化、事后秩序或旁人反应等非露骨表达。色情或敏感接触会改写为肩侧、手臂、背部外侧、衣袖、衣角、门框距离、两人站位等安全部位和相对位置；血相关视觉词会改写为红色液体或暗色痕迹。`prompt` 的 `[台词/旁白]` 行属于阅读内容，必须保留原文，不做安全改写。

分镜生成会优先按内部旁白语速合并短句：短句会尽量与相邻句合并为同一个分镜单元，但每个镜头覆盖的旁白朗读估算不超过 8 秒。中文按约 6 个阅读单位/秒估算，英文按约 2.4 词/秒估算；人物、动作、视角或场景发生切换时会补充反应镜头、第三方视角、场景空镜或建立镜头。

分镜表和导出文件里的秒数是镜头画面时长，不是阅读时长。普通镜头通常估算为 3-6 秒，反应镜头约 2-3 秒，场景空镜/建立镜头约 2-4 秒；无旁白的反应镜头和空镜默认按约 2 秒估算。

导出的 CSV 和 Excel 会对提示词列做格式化：`[00:00-00:00s]`、`[镜头语法]`、`[画面细节]`、`[摄影机补充状态]`、`[声音设计]`、`[台词/旁白]`、`[导演批注]` 会各自保留为单元格内独立行。Excel 导出会写入单元格内换行标记，复制时保留换行。

分镜表和 CSV/Excel 中的“镜头编号”是集内编号，会随 `episodeNumber` 每集重新从 1 递增；JSON 项目文件里的 `index` 保留全片全局顺序，便于恢复项目和排查流式生成顺序。

## 当前限制

- v1 不包含登录、团队协作、云端项目库。
- v1 不直接调用即梦、可灵、Runway 等视频生成平台。
- 整本小说是一次点击生成；内部会按文本长度分段，但还没有可视化队列、暂停、断点续跑。
- 阅读速率 `0.95` 的最终口径还未定，目前按 `秒/字` 作为默认值，并允许在 UI 中修改。
- 提示词是通用中文提示词，不包含特定平台参数，并会对高风险视觉内容做非露骨表达和输出清洗。

## 当前开发状态

- API 配置、模型下拉、本地保存、英文自动译文、长文分段并发和分批理解合并已经接入。
- 当前长文策略：理解阶段约 `2200` 字分段；分镜阶段再拆成短 `【分镜单元】`，每个请求最多 `16` 个镜头，并发上限默认 `2`，理解合并在本地确定性完成，分镜阶段按段流式追加显示。
- 当前失败续跑策略：分镜阶段失败后，前端记录失败段和已生成镜头，错误栏会追加“可点击继续重试”的下一步提示；用户可从失败段串行生成剩余分段，避免从头重跑。
- 当前理解失败处理策略：理解阶段连接错误或临时失败后，前端会标记为生成中断并显示“重新尝试理解”，保留正文、设置和项目历史，不再误提示只能使用分镜续跑。
- 当前 TXT 队列策略：一次可导入多个 `.txt` 文件，每个文件会保存为独立本地项目；用户手动选择某一集载入并创作，避免批量自动生成遇到 503 或超时后整批难恢复。
- 当前历史记录策略：IndexedDB 保存所有导入和创作过的项目，记录文件名、正文、设置、理解档案、分镜结果、更新时间和状态；页面可重新打开旧项目、删除本地记录或导出同名 Excel。
- 当前弹性生成策略：分镜提示词携带“分段相关理解档案”，只保留本段命中的人物/场景/关键事件/连续性提示，并补充前后相邻段锚点，在减少上下文的同时保留局部一致性；单次模型请求有超时边界；临时失败会先退避重试，再自动拆小当前分段继续生成。
- 当前理解合并策略：合并阶段不再请求模型；后端会本地去重人物、场景、关键事件、情绪节奏和连续性提示，并按 schema 限制截断，避免长篇合并阶段卡死或超时。
- 当前英文分镜策略：按词数拆分长句时会重平衡过短尾段，避免句末单词被单独作为旁白镜头；英文逗号/分号/冒号拆分只允许发生在引号外，避免 `"Lucy, come downstairs."` 这类对白被拆成两段。
- 当前对白边界策略：英文和中文直接引语不跨前一句叙述合并，模型提示词也禁止跨 `【分镜单元】` 合并原文字段。
- 当前英文对白策略：完整引号对白不会被内部问号或感叹号直接打碎，英文弯引号 `“...”` 也按完整 quote 处理；引号闭合后同一句的动作/反应可跟随到同一分镜单元。若后续英文叙述句接近镜头朗读上限且有逗号，会按逗号保守拆分；如果长对白因长度拆成多个分镜单元，每段仍保留引号并要求模型继承同一说话人。原文保真修复层同时支持英文双引号和成对单引号对白，并避免把 `Vivian's` 这类所有格撇号误判成对白。
- 当前模型调用策略：优先 Responses API 结构化输出，遇到第三方网关 Responses 格式不兼容时自动回退到 Chat Completions。
- 当前提示词安全策略：模型提示中要求高风险情节安全画面化，后端会清洗视频生成字段中的敏感视觉词；色情/敏感接触改写为安全部位和相对位置，血相关表达改为红色液体或暗色痕迹。`sourceText`、`narration`、`dialogueLines.text` 和 `prompt` 的 `[台词/旁白]` 阅读行必须保留原文，不做任何改写。
- 当前原文保真策略：分镜模型返回后，后端会把每个镜头重新绑定到原始 `【分镜单元】`，用原始分镜单元修复 `sourceText`、`narration`、`dialogueLines.text` 和 `[台词/旁白]` 行；模型遗漏的分镜单元会补保底镜头，模型额外生成且不在原文中的台词会被移除。
- 当前场景和人物策略：已取消“场景/人物不确定就降级或保守重建”的后处理层；`scene`、`characters`、`imageDescription` 和 prompt 视觉行以模型输出为主，只做安全画面化清洗和原文阅读行修复。这样优先保证每个镜头有可参考的具体画面，而不是大量输出空白或保守占位。
- 当前质检策略：分镜修复后会生成内部质量报告，并把摘要追加到 notes；质检会检查 prompt 固定标签、阅读行一致性等问题。阅读行一致性检查会忽略 `【停顿0.4s】` 这类口型控制标记，避免把正确停顿误报为原文不一致。
- 当前镜头语言策略：默认保持单一景别、焦距和焦点，只有有明确叙事原因时才使用单镜头内景别切换、焦距变化、焦点转移；全身/半身人物描写要求补齐表情细节、手部动作、身体姿态、视线方向，面部/近景/特写要求补齐嘴角状态、眼部状态、面部状态、视线方向，并加入高级动画感审美指引。
- 当前导出策略：提示词列会在 CSV 和 Excel 中按固定镜头标签格式化换行，角色对白列也保留单元格内多行。
- 当前编号策略：界面和 CSV/Excel 使用每集内镜头编号，JSON 保留全局镜头 `index`。
- 下一步优先建议：增加分段级进度条、失败段重试、暂停/继续，以及 API 请求日志面板，方便定位长文生成失败。
