# 解说剧分镜工坊

一个面向小说解说剧生产的本地网页工具。它把小说正文拆解为可编辑的分镜表，并为每个镜头生成通用中文画面提示词。

当前版本是 v1 原型：单人本地使用，不做账号系统，不做云端数据库，不要求登录。

## 功能

- 选择视觉风格：`2D`、`3D`、`3D高精度CG`、`仿真人`，并提供常驻“视觉描述”输入框，可直接填写更明确的自定义风格
- 选择网文解说剧本风格：爽文、悬疑、言情、玄幻、都市、惊悚，也可以输入自定义剧本风格
- 选择语言：中文或英文
- 设置阅读速率，默认 `0.95 秒/字`
- 设置目标分集数，生成后在分镜表和导出文件中标记分集
- 支持一次导入多个 `.txt` 文件，每个文件作为独立本地项目/单集进入队列，可逐个载入处理
- 本地历史记录保存在 IndexedDB，可查看、切换、删除旧项目，并从历史记录重新打开继续处理
- 分镜表和 CSV/Excel 导出的镜头编号按每集重新从 1 开始，JSON 仍保留全片全局 `index`
- 在页面内临时配置模型、API Key 和 Base URL，方便本地测试不同 API
- 应用 API 配置后自动读取当前可用模型，并支持手动刷新模型列表
- API 配置会保存在当前浏览器本地存储，刷新后自动恢复并重新连通后端
- 创作前会检查 API 连通状态，开始后显示当前理解/分镜生成阶段
- 英文输入会自动生成中文译文，方便对照查看
- 粘贴长英文或中文文本时会自动识别语言，并同步切换阅读单位，减少长文误用中文统计口径
- 输入整本小说，生成前展示字数、句数、预计分段和阅读总时长
- 独立理解阶段：提取人物、场景、关键事件、情绪节奏和连续性提示；长文会先分段理解，再在本地合并并做原文证据过滤
- 理解档案面板默认压缩为内部滚动区域，长档案可以展开查看，避免撑开整个工作台
- 理解档案进入分镜前会做证据验收：人物名、场景名/地点、关键事件和连续性提示必须能被当前原文支持；只有道具 visualAnchor 命中时，不会单独推断具体地点
- 分镜生成阶段：先按约 `2200` 字的小段拆分，再并发生成分镜，降低上下文过长导致的漂移风险
- 分镜阶段会再次拆成“分镜单元”，短句会在上下文连续时合并成较长镜头，适配视频生成长度限制
- 英文分镜单元会自动重平衡过短尾句，避免把句末单词单独拆成一个镜头
- 英文直接引语会作为硬边界处理，避免上一句尾词和下一句对白粘连
- 英文长对白即使被拆成多个分镜单元，每个片段也会保留引号形态，便于模型继承说话人并识别为对白
- 分镜表中的秒数表示镜头画面时长，不再等同于旁白阅读时长
- 人物、动作、视角或场景切换时，提示词会要求补齐第三方反应镜头或场景空镜，增强镜头之间的连贯性
- 引号内的直接发言会优先识别为角色对白，即使原文没有明确写说话人，也不会降级成旁白
- 长文生成改为分段流式返回：理解阶段显示进度，分镜阶段每完成一段就把该段镜头追加到表格，不再等整本全部完成
- 生成中可以取消，已生成的分镜会保留并进入本地自动保存
- 理解阶段遇到连接错误或临时失败后，页面会保留当前文本和设置，并提供“重新尝试理解”入口，不需要手动刷新或重新粘贴正文
- 分镜阶段遇到 `503 system cpu overloaded`、`Connection error` 等临时失败后，页面会保留已完成分段，并在错误栏和状态栏明确提示可从失败段“继续重试”，不需要重跑理解阶段和已成功分镜段
- 每个模型返回镜头都会经过视觉可靠性验收；具体无证据场景、无证据医院/手术空间、空白占位画面会用当前分镜单元和前后 1 个单元/镜头重写为具体可拍画面。开头或世界观信息缺少场景时，会只使用附近原文明确出现的强场景锚点（如 `Summoning Hall`、`Aurelia Academy`、`Binding Rite`）补足可拍空间；无证据额外人物、泛称人物（如陌生人、路人、someone/person）或单独医护人员会优先做局部清洗，保留模型原本可用画面，不再把轻微问题整条替换成“可靠性修复镜头”。仅 `scene` 字段写成“未明确场景”不会单独触发整镜头重写
- 提示词按镜头制作格式输出：时间段、镜头语法、画面细节、摄影机状态、声音设计、台词/旁白、导演批注；镜头语法支持景别切换、焦距变化和焦点转移；近景/特写强化表情细节，其他景别优先写清动作和人物站位；提示词主体为中文，台词/旁白引用内容保留原文语言
- 提示词生成增加安全画面化规则：敏感或高风险情节会在画面、镜头、声音和导演批注中改为非露骨影视表达；旁白和对白阅读内容必须保留原文，不做任何改写
- 分镜表内编辑：旁白、落点句、画面描述、镜头类型、角色、场景、情绪、提示词
- 分镜表将提示词独立展示为导演工作台，主字段行会同步拉伸高度，便于长内容校对
- 本地 IndexedDB 自动保存项目状态
- 导出 `CSV`、`Excel` 和 `JSON`；从 `.txt` 导入的项目会按原文件名导出同名 Excel，例如 `ep01.txt` -> `ep01.xls`
- 历史记录中已生成分镜的项目支持单独导出 Excel，也支持一键导出全部已完成项目的同名 Excel
- 导出时提示词列会按镜头标签保留单元格内换行，便于复制到视频生成工具

## 技术栈

- Frontend: Vite + React + TypeScript
- Backend: Node.js + Express
- AI: OpenAI Responses API + Structured Outputs
- Local storage: IndexedDB
- UI icons: lucide-react

## 快速开始

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

打开：

```text
http://localhost:3000/
```

后端默认运行在：

```text
http://localhost:8787
```

## OpenAI 配置

如果只是查看界面，不需要配置 API Key。

如果要真实生成理解档案和分镜，需要在项目根目录创建 `.env`：

```bash
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-6.1-sol
OPENAI_BASE_URL=
PORT=8787
MODEL_REQUEST_TIMEOUT_MS=90000
MODEL_PROBE_TIMEOUT_MS=15000
PARALLEL_CHUNK_LIMIT=1
TRANSIENT_REQUEST_RETRIES=3
TRANSIENT_RETRY_BASE_DELAY_MS=1000
TRANSLATION_BASE_URL=https://translate.googleapis.com/translate_a/single
TRANSLATION_FALLBACK_URL=https://api.mymemory.translated.net/get
TRANSLATION_REQUEST_TIMEOUT_MS=30000
```

可参考 `.env.example`。

说明：

- API Key 只在后端读取，不会进入前端 bundle。
- 默认模型是 `gpt-6.1-sol`。读取网关模型列表后会优先选择精确的 `gpt-6.1-sol`，其次选择同系列 `6.1-sol` 模型和 `gpt-6-sol`；网关未列出手填模型时会保留手填值并要求重新测试，不会静默替换成无关模型。
- 如果当前账号无法使用该模型，后端会返回明确错误。可以通过 `OPENAI_MODEL` 改成可用模型。
- 页面中的 API 配置会覆盖当前运行中的本地后端配置，并保存在当前浏览器本地存储；不会写入 `.env`。
- 如果使用第三方模型网关，`OPENAI_BASE_URL` 或页面里的 Base URL 必须填写 OpenAI-compatible API 根地址，通常以 `/v1` 结尾；不要填写网关控制台首页，否则后端会收到 HTML 页面而不是 JSON API 响应。
- 机器翻译服务的单次查询上限按 500 字符处理，程序会把英文正文拆成每段最多 450 字符的翻译请求，并在合并译文时恢复原文分段之间的空格和换行边界，避免 `QUERY LENGTH LIMIT EXCEEDED`。
- 如果网关返回 `502 Upstream request failed`、`invalid character ... looking for beginning of value` 或其他非 JSON 响应，通常表示第三方网关或上游模型临时返回异常；系统会自动重试一次，持续出现时可降低并发或切换模型。
- 如果网关返回 `503 system cpu overloaded`，通常表示上游模型服务临时过载；系统会按指数退避自动重试，仍失败时建议把分段并发降到 `1`、稍后重试或切换可用模型。
- 如果网关返回 `Connection error`、`network error`、`ECONNRESET`、`ECONNREFUSED` 等连接错误，系统会按临时错误处理并进入指数退避重试；理解阶段仍失败时可在页面直接重新尝试理解，分镜阶段仍失败时可用“继续重试”从失败段续跑。
- 所有 Responses 请求都会携带 `instructions` 字段，以兼容要求 `Instructions are required` 的第三方网关。
- 所有 Responses 请求的 `input` 都使用消息数组打包，以兼容要求 `Input must be a list` 的第三方网关。
- 理解阶段的模型输出 schema 已与 OpenAI Structured Outputs 兼容：模型专用 schema 中新增证据字段使用 required + nullable，避免 `.optional()` 字段触发 `all fields must be required` 错误；API 入参仍兼容旧项目中没有 evidence 的理解档案。
- 如果第三方网关的 Responses API 兼容不完整，后端会自动回退到 Chat Completions JSON Schema；如果 JSON Schema 也不兼容，会再回退到普通 Chat Completions 并手动解析 JSON。
- 后端错误处理有本地 mock 测试覆盖，确保非 JSON 网关错误不会被误报为模型无权限，并避免真实模型不存在时触发无效回退。
- 分段并发数量可通过 `PARALLEL_CHUNK_LIMIT` 配置，默认 `1`，非法配置时兜底为 `1`，最大限制为 `6`。如模型网关限流较宽松，可调高到 `2-6`。
- 临时网关错误重试次数可通过 `TRANSIENT_REQUEST_RETRIES` 配置，默认 `3`，最大限制为 `6`；退避基础间隔可通过 `TRANSIENT_RETRY_BASE_DELAY_MS` 配置，默认 `1000` 毫秒。
- 如果模型网关返回 `429`、`rate_limit` 或 `too many requests`，系统会按退避策略重试；连续失败时不会继续拆分分镜段，以免在限流或额度不足时增加请求量。建议将 `PARALLEL_CHUNK_LIMIT=1`，检查网关的额度、RPM/TPM 限制，或更换模型与 Base URL。
- 分镜单次模型请求超时可通过 `MODEL_REQUEST_TIMEOUT_MS` 配置，默认 `90000` 毫秒；分镜超时会直接尝试自动拆小段继续生成，其他临时网关错误按退避策略重试。
- 分镜请求超时不会重复重试同一个完整分段，而是直接进入自动拆小段流程；502、503、连接中断等网关瞬态错误仍按退避策略重试。这样可以避免一个 90 秒超时段被连续重试多次后才拆分。
- 页面“读取模型”只验证模型列表接口；“测试模型”会向当前选定模型发送一次只回复 `OK` 的轻量请求，并显示实际使用的 Responses 或 Chat Completions 通道及耗时。只有测试成功后才能开始生成。测试超时可通过 `MODEL_PROBE_TIMEOUT_MS` 配置，默认 `15000` 毫秒。
- 分镜超时日志只记录阶段、模型、Base URL、超时阈值和请求字符数，不记录 API Key 或正文；可据此判断是否是固定时限触发，并结合网关日志继续区分排队、上游拥塞、模型推理耗时和网络延迟。
- 理解阶段请求超时可通过 `ANALYSIS_REQUEST_TIMEOUT_MS` 配置，默认 `180000` 毫秒。理解合并不再调用模型，而是在本地确定性去重、截断和合并，避免长篇合并阶段卡死或超时。
- 分镜段自动拆分重试深度可通过 `MAX_STORYBOARD_ADAPTIVE_SPLIT_DEPTH` 配置，默认 `2`，最大 `4`。当某个分镜段因 503、超时、非 JSON 等临时错误失败时，后端会把该段按 `【分镜单元】` 拆成更小子段重试，降低长段卡死和整段失败概率。
- 本地稳定性排查可启用 `JSSTORY_MOCK_AI=1`，它会绕过真实模型并返回 mock 结构化结果；配合 `JSSTORY_MOCK_STORYBOARD_FAIL_UNIT_LIMIT` 可以模拟大分镜段返回 `503 system cpu overloaded`，用于验证自动拆分重试和流式事件是否正常。
- 生成中前端会显示本地运行时长和“距离上次后端事件”的秒数；后端流连接建立后会发送 `heartbeat` 事件，用于区分页面无反馈、网络断开和模型/网关仍在处理。
- 分镜阶段输入会拆成 `【分镜单元】`，短句会在上下文连续、人物/动作/场景关系清楚时与相邻句合并，每个单元尽量对应一个镜头，单镜头旁白朗读估算不超过 `12` 秒。
- `durationSeconds` 表示镜头画面时长，用于视频生成和剪辑节奏；页面阅读速率只用于正文总时长估算，不直接决定分镜单元和镜头秒数。
- 每个分镜请求最多允许模型输出 16 个镜头，优先保证短镜头和动作连续性，而不是把多句旁白合并成长镜头。
- 理解结果合并不再请求模型递归合并；后端会本地去重、截断并过滤无证据人物/场景/关键事件/连续性提示，避免合并阶段重新形成超长上下文或把模型幻觉传给分镜。

## 使用流程

1. 在顶部确认 API 配置，默认会沿用本地 `.env` 或当前环境变量中的 API。
2. 点击“应用配置”后，系统会读取当前 API Key 和 Base URL 可用的模型列表。
3. 选择视觉风格、剧本风格、语言、阅读速率和目标分集数；需要更精确画面风格时，可直接编辑“视觉描述”。
4. 在小说正文区域粘贴文本；如果语言是英文，系统会自动生成中文译文。
5. 检查系统估算的阅读单位、句数、预计分段和总时长。
6. 点击“生成分镜与提示词”。
7. 点击后系统会立即显示状态：先执行理解阶段，再并发执行分段分镜阶段。
8. 在分镜表中按分集人工校对和编辑。
9. 导出 CSV、Excel 或 JSON。

## API

### `GET /api/config`

返回当前后端模型和 API Key 配置状态。

### `POST /api/config`

临时更新当前运行中的本地后端配置：

- `model`
- `apiKey`
- `baseURL`

### `GET /api/models`

返回当前 API Key 和 Base URL 下可读取到的模型 ID 列表。

### `POST /api/models/check`

向当前模型发送轻量连通性测试请求，验证模型实际生成能力；返回模型 ID、使用的 API 通道和耗时。

### `POST /api/translate`

输入英文正文，返回中文译文，用于英文模式下的本地对照查看。该接口直接调用机器翻译服务，不需要 OpenAI API Key，也不会调用当前配置的 LLM。默认先请求 Google Translate 非官方兼容接口，失败后自动尝试 MyMemory 备用服务；可分别通过 `TRANSLATION_BASE_URL` 和 `TRANSLATION_FALLBACK_URL` 替换服务地址。两个服务都不可用时，页面会保留英文原文并继续生成英文分镜，不会因为翻译失败阻塞创作。

### `POST /api/analyze`

输入小说正文和参数，返回理解档案：

- 故事钩子
- 人物设定
- 场景清单
- 关键事件
- 情绪节奏
- 连续性提示

### `POST /api/storyboard`

输入小说正文、参数和理解档案，返回分镜结果：

- 镜头编号
- 分集编号
- 原文句组
- 落点句
- 旁白
- 角色对白
- 画面描述
- 镜头类型
- 角色
- 场景
- 情绪
- 通用中文提示词
- 镜头画面时长

### `POST /api/generate/stream`

输入小说正文和参数，返回 `application/x-ndjson` 流式事件。当前是分段级流式，不是 token 级流式：结构化模型调用仍然需要等单段 JSON 完成后才能解析，但前端会在每段分镜完成时立即追加显示。
分镜流式过程中的分集编号是临时显示，`done` 事件会返回最终重排后的完整 `shots`，前端会自动替换，保证完成后的表格和导出文件分集编号一致。

事件包括：

- `heartbeat`
- `started`
- `analysis_started`
- `analysis_chunk`
- `analysis_merge`
- `analysis_merge_progress`
- `analysis_completed`
- `storyboard_started`
- `storyboard_progress`
- `storyboard_chunk`
- `done`
- `error`

客户端取消或断开连接后，后端会停止继续派发新的分段请求，并向 OpenAI SDK 请求传递取消信号，尽量减少取消后继续消耗 API 的情况。

### `POST /api/generate/storyboard/resume`

用于分镜阶段失败后的手动续跑。前端会传入原文、设置、已完成的理解档案、已生成镜头和失败分段索引；后端只从失败分段继续生成剩余分镜，并继续通过 NDJSON 返回：

- `storyboard_started`
- `storyboard_chunk`
- `done`
- `error`

续跑接口会保留已有镜头，完成后重新分配最终分集编号。为了提高 503 过载后的成功率，续跑阶段按剩余分段串行处理。

## 提示词格式

分镜的 `prompt` 字段会按固定镜头格式生成：

```text
[00:00-00:00s]
[镜头语法 / 视角 / 景别 / 焦距 / 焦点变化 // 运动或强度]
[画面细节] 主体、动作、空间、构图、光线、色彩、关键道具、视觉风格；必须包含当前场景光源，至少写清主光源来源、光线方向、光线质感；近景、特写、面部或细节镜头会补足表情细节、嘴角状态、眼部状态、面部状态、视线方向；中景、全景、远景、全身、半身或多人同框会优先写清动作路径、人物站位、距离关系、身体姿态/朝向、手部动作和视线关系，避免堆叠过细微表情；如果是主观视角，会明确是谁的视角。
[摄影机补充状态] 机位高度、运动方式、稳定程度、推拉摇移、景深、畸变或遮挡；需要时写清楚焦距变化、焦点转移和跟焦节奏。
[声音设计] BGM、环境声、拟音、情绪推进、音量或节奏变化。
[台词/旁白] 旁白：“对应原文内容”；角色名（情绪+发声方式）：“对应原文内容”。没有明确说话人时写：未指明说话者（情绪+发声方式）：“对应原文内容”。没有旁白或对话时写：无。
[导演批注] 镜头的戏剧目的、观众感受、剪辑或同框重点。
```

提示词主体必须使用中文，包括镜头语法、画面细节、摄影机补充状态、声音设计和导演批注。

镜头语法会按镜头功能选择焦段、景深和焦点状态：建立镜头偏 24mm 深景深，动作中景偏 35mm-50mm 跟焦，近景/特写偏 70mm/85mm 浅景深。只有同一分镜单元确实存在情绪推进、动作结果、视线转移、信息揭示或叙事落点变化时，`[镜头语法]` 才表达为类似 `35mm -> 50mm` 或 `中景 -> 近景`，并说明切换原因、焦距变化和焦点转移；没有变化时也必须写清当前焦段、景深和焦点落点。视觉风格加入审美指引：高级动画感，不是越真实越好，而是把真实的空间、光影和材质，控制在一个更有审美的动画世界里；该指引不改变安全画面化和对白/旁白边界规则。

旁白和所有角色对话都必须使用中文双引号；双引号里的内容保持原文语言，不翻译。英文小说的旁白/对白仍写英文，中文小说的旁白/对白仍写中文。原文中被中文或英文引号包裹的直接发言必须作为角色对白输出，不能混入旁白；角色名和 speaker 不能使用 `他`、`她`、`它`、`he`、`she`、`it`、`they` 这类代称，必须使用完整人物称谓；确实无法判断说话人时使用 `未指明说话者`。没有旁白或对话时，`[台词/旁白]` 行写 `无`。

解说剧阅读顺序严格跟随原文。英文 `"对白," Elena said.` 这类归属语不能删除，也不能改写；引号内内容作为 `Elena` 的角色对白读出，后面的 `Elena said.` 作为旁白继续读出，并在对白切到旁白时插入 `【停顿0.8s】`。如果下一句是紧邻的单独引号对白且说话人未明，会优先继承上一句明确归属语里的 speaker。

如果同一个镜头的 `[台词/旁白]` 行同时包含旁白和角色对白，两段阅读之间必须插入停顿标记。角色对白切到旁白时使用 `【停顿0.4s，角色名静默无发声】`，例如：`角色名（紧张+低声）：“原文对白”；【停顿0.4s，角色名静默无发声】；旁白：“原文旁白”`。旁白切到角色对白时使用普通 `【停顿0.4s】`。停顿标记不能放进双引号里，不能改变阅读原文；画面上应在停顿处切到闭口反应、旁观者、手部动作或环境物件，避免角色说完台词后继续张嘴承接旁白造成穿帮。

英文完整引号对白会先作为完整句识别；如果因为长度需要拆成多个分镜单元，每个片段也会重新包上引号，避免变成无引号旁白碎片。模型规则要求这些拆分片段继续作为 `dialogueLines` 输出，并从上下文、相邻对白片段和理解档案继承同一说话人。

视频生成相关字段会执行安全画面化处理。`sourceText`、`narration` 和 `dialogueLines.text` 保留原文，方便校对；`imageDescription`、`shotType`、`emotion` 和 `prompt` 的画面/镜头/声音/导演批注行会避免露骨血腥、伤害过程、身体细节、违法操作步骤、性化未成年人、仇恨羞辱等内容，并改写为远景、遮挡、剪影、声画错位、道具倒落、环境变化、事后秩序或旁人反应等非露骨表达。色情或敏感接触会改写为肩侧、手臂、背部外侧、衣袖、衣角、门框距离、两人站位等安全部位和相对位置；血相关视觉词会改写为红色液体或暗色痕迹。`prompt` 的 `[台词/旁白]` 行属于阅读内容，必须保留原文，不做安全改写。

理解档案和视觉镜头都会做证据验收。理解阶段中，人物、场景、关键事件和连续性提示必须能被当前原文支持，只有道具或氛围词命中时不会单独证明具体地点。分镜阶段中，模型返回的每个镜头都会先绑定回原始 `【分镜单元】`，再检查场景和视觉实体是否有当前单元、前后 1 个单元/镜头或已验证理解档案支撑；人物名只接受当前分镜单元的文本证据，代词句只能从上一镜头继承人物，不从下一句或附近场景锚点借人名。无证据具体场景无论出现在 `scene` 字段还是 `[画面细节]` 里，都会触发可靠性重写。无证据医院、手术台、空白背景或标题词误识别同样会触发可靠性重写；`doctor/医生` 只证明医护人物，不自动证明医院、急救室或手术台。无证据额外人物、泛称人物或单独医护人员会优先局部清洗视觉行和角色数组，导演批注追加“视觉局部修复”，不再整条改成“可靠性修复镜头”。仅 `scene` 字段保守写“未明确场景”时会作为质检提示保留，不单独触发重写，避免正常可用画面被过度替换。可靠性修复只改视觉字段和提示词结构，`sourceText`、`narration`、`dialogueLines.text` 与 `[台词/旁白]` 阅读行仍按原文重建。

分镜生成会优先按内部旁白语速合并短句：短句会在上下文连续、人物/动作/场景关系清楚时与相邻句合并为同一个分镜单元，但每个镜头覆盖的旁白朗读估算不超过 12 秒。合并必须以完整句、完整直接引语或完整动作链为边界，不能为了凑时长把一句话切成不完整片段，也不能跨明显人物、动作、视角、场景、时间或直接引语边界。中文按约 6 个阅读单位/秒估算，英文按约 2.4 词/秒估算；人物、动作、视角或场景发生切换时会补充反应镜头、第三方视角、场景空镜或建立镜头。

分镜表和导出文件里的秒数是镜头画面时长，不是阅读时长。普通镜头通常估算为 4-8 秒；同一场景内连续动作、情绪推进或环境描写可以到 8-12 秒；反应镜头约 2-3 秒，场景空镜/建立镜头约 2-4 秒；无旁白的反应镜头和空镜默认按约 2 秒估算。

导出的 CSV 和 Excel 会对提示词列做格式化：`[00:00-00:00s]`、`[镜头语法]`、`[画面细节]`、`[摄影机补充状态]`、`[声音设计]`、`[台词/旁白]`、`[导演批注]` 会各自保留为单元格内独立行。Excel 导出会写入单元格内换行标记，复制时保留换行。

分镜表和 CSV/Excel 中的“镜头编号”是集内编号，会随 `episodeNumber` 每集重新从 1 递增；JSON 项目文件里的 `index` 保留全片全局顺序，便于恢复项目和排查流式生成顺序。

## 当前限制

- v1 不包含登录、团队协作、云端项目库。
- v1 不直接调用即梦、可灵、Runway 等视频生成平台。
- 整本小说是一次点击生成；内部会按文本长度分段，但还没有可视化队列、暂停、断点续跑。
- 阅读速率 `0.95` 的最终口径还未定，目前按 `秒/字` 作为默认值，并允许在 UI 中修改。
- 提示词是通用中文提示词，不包含特定平台参数，并会对高风险视觉内容做非露骨表达和输出清洗。

- 当前对白边界策略：英文和中文直接引语不跨前一句叙述合并，模型提示词也禁止跨 `【分镜单元】` 合并原文字段。
- 当前英文对白策略：完整引号对白不会被内部问号或感叹号直接打碎，英文弯引号 `“...”` 也按完整 quote 处理；连续多段引号对白会优先按每个完整 quote 分镜，避免 `"Out with the old..."` 这类对白被按词切成 `Out with / the old`；按词数拆分长 quote 时会额外重平衡介词、冠词和 `Out with the old` 这类短语边界，避免输出 `Out with”` 或下一段以 `the old` 开头；引号闭合后同一句的第一人称动作/反应可跟随到同一分镜单元，闭合引号后接 `Inside/Leo/The...` 这类新叙事或场景句时会断开，避免长对白被按词切成 `wi / n on`。若后续英文叙述句接近镜头朗读上限且有逗号，会按逗号保守拆分；如果长对白因长度拆成多个分镜单元，每段仍保留原来的直引号或弯引号，并要求模型继承同一说话人。中文分镜不再按顿号拆开列表，避免钥匙、手机、旧照片这类并列物件被切成多个无意义镜头。原文保真修复层同时支持英文双引号和成对单引号对白，并避免把 `Vivian's`、`didn’t` 这类所有格或撇号误判成对白。
- 当前模型调用策略：优先 Responses API 结构化输出，遇到第三方网关 Responses 格式不兼容时自动回退到 Chat Completions。
- 当前提示词 skill 策略：后端新增内部 `Prompt Skill Set` 模块，不使用 OpenAI tools/function calling，也不让模型自行决定调用；理解阶段注入 `evidence-first-analysis`，分镜阶段注入 `original-text-fidelity`、`speech-ordering`、`scene-evidence`、`cinematic-image-quality`、`visual-safety`。这些 skill 是调用前确定性拼入 prompt 的精简规则入口，用来固定原文保真、对白顺序、场景证据、画面质量和安全画面化的优先级；当前第一版先建立模块边界和测试覆盖，后续再逐步压缩原长 prompt 中的重复说明以控制 token 增量。
- 当前提示词安全策略：模型提示中要求高风险情节安全画面化，后端会清洗视频生成字段中的敏感视觉词；色情/敏感接触改写为安全部位和相对位置，血相关表达改为红色液体或暗色痕迹。`sourceText`、`narration`、`dialogueLines.text` 和 `prompt` 的 `[台词/旁白]` 阅读行必须保留原文，不做任何改写。
- 当前原文保真策略：分镜模型返回后，后端会把每个镜头重新绑定到原始 `【分镜单元】`，用原始分镜单元修复 `sourceText`、`narration`、`dialogueLines.text` 和 `[台词/旁白]` 行；模型遗漏的分镜单元会补保底镜头，模型额外生成且不在原文中的台词会被移除。
- 当前保底镜头策略：模型漏掉分镜单元时，后端会根据当前原文、前后分镜单元和最近已知镜头上下文生成可拍摄的 `imageDescription`、场景、人物、动作延续、光源和摄影机补充状态，不再把完整原文机械贴进 `[画面细节]`，也不再输出“执行当前句动作”或“安全画面”占位模板；保底修复会过滤标题式场景和 `From/In/Fate/Written/Bloodline` 这类功能词或标题词，避免出现 `Fate Written in Bloodline中，From...`；但 `[导演批注]` 固定保留 `保底修复镜头，用于补齐模型遗漏的原文分镜单元。`，方便人工筛查。
- 当前可靠性修复画面策略：即使镜头被标记为 `可靠性修复镜头`，也必须输出可拍摄的自然语言画面，不再使用 `画面主体`、`当前叙事重点`、`关键道具`、`空间入口` 等占位词。若原文或 `dialogueLines` 已经明确说话人，修复画面会写清谁在说话、人物动作、嘴角/眼部/微表情、周围人物反应、前景/背景/氛围和光源；画面中有人物时会追加 `保持人物面部清晰，自然柔和瞳孔聚焦`，该指令只影响视觉生成，不改变 `[台词/旁白]` 原文阅读行。
- 当前开头场景锚点策略：抽象世界观、血脉规则、等级规则等开头分镜单元如果当前句和相邻 1 句没有明确场景，会向附近少量分镜单元扫描强场景证据，只接受原文明确出现的 `Summoning Hall`、`Aurelia Academy`、`Binding Rite` 等地点/仪式锚点，并把画面改写为包含具体空间、祭坛/兽卵/符文、光源和前中后景关系的可拍镜头。`世界观建立画面`、`当前连续场景`、`前世记忆画面` 这类泛化标签不会再被当作相邻镜头的明确场景证据；`previous life / past life / Pact Backlash` 等时间或事件词也不会单独覆盖当前已证实空间。
- 当前阅读顺序策略：`[台词/旁白]` 行按原文顺序重建，英文 `"对白," Elena said.` 会输出为 `Elena：“对白,”；【停顿0.8s】；旁白：“Elena said.”`；归属语仍作为旁白保留，不会删除。单个分镜单元内如果同时存在前置旁白、角色对白和后置旁白，会按“旁白 -> 停顿0.4s -> 对白 -> 停顿0.8s -> 旁白”的原文顺序输出；连续两个引号对白不会把第二句降级成旁白。紧邻的下一句单独对白会优先继承上一句明确 speaker。
- 当前场景和人物策略：不再让 `scene`、`characters`、`imageDescription` 和 prompt 视觉行无条件沿用模型输出。模型输出会先经过安全画面化清洗、人物代称清理和原文阅读行修复，再做视觉可靠性验收；具体无证据场景、医院/手术台、空白背景或标题词误识别会用当前分镜单元和前后 1 个单元/镜头重写。无证据额外人物、泛称人物或单独医护人员会先做局部清洗，移除对应视觉片段和角色数组项，保留原镜头可用的主体动作、光源和构图，避免可靠性修复镜头泛滥。仅 `scene=未明确场景` 不再单独触发重写；它会作为低置信场景质检提示保留。`characters` 会移除 `他/她/它/he/she/it/they/I/me/my/we` 等代称，并会补入已明确的对白说话人；保底镜头会在生成画面前先按原文和上一位 speaker 推导 `dialogueLines`，纯引号对白可继承上一句明确说话人，第三人称归属语如 `she asked` 会优先从前文最近的非第一人称角色继承，避免画面主体落成 `空间结构` 或误归为第一人称。第一人称对白会优先归属到理解档案中有明确主角证据的人物名，没有明确主角证据时使用 `第一人称主角`，不会再把理解档案里的第一个人物默认当成叙述者；同时只读取引号外的 `I/me/my` 证据，避免角色台词里的 `I want you...` 污染人物数组。人物名的文本证据只来自当前分镜单元；代词句需要补全人物时只允许从上一镜头继承人物，`it/its` 遇到中间插入角色台词时会向前寻找最近的非第一人称主体；若原文有 `devoured/scales/dragon/bone/scroll` 等非人物动作，会优先继承最近的兽类或物件主体，避免误落到 Victoria 这类人物。场景推断优先使用当前句引号外叙事和已继承场景；对白或叙事里只是提到 `hospital`、`budget cuts`、`barrier`、`law` 等对象关系时不会单独把当前镜头切到医院，`last life/back then/critically ill` 等明确回忆提示也会保持保守，不让医院光源污染当前场景；`Lifebloom Stag core`、`Royal Vault`、`front hall`、`silver altar`、`Core Crystals`、`Divine Matter`、`relics` 等会作为宝库场景锚点处理，普通 `door` 不再把整段宝库内部污染成“门口/走廊”。英文人物抽取会先剥离引号对白和方括号系统文本，避免 `Take/Eat/Not/Consumed/Passive/Seven/Back/Half` 这类 quote-leading、时间副词或系统标签词被当作人物；中文视觉文本抽取会要求中文词边界，避免把 `第一人称主角说出对白时` 截成 `称主角/对白时/方向和` 这类假人物。英文玄幻标题词、物种词、机构/赛事词、场景词和句首功能词（如 `One-Star Reject`、`Aether Beast`、`Royal Vault`、`Augustine Empire`、`Imperial Capital`、`Beastmaster Grand Tournament`、`Holy See`、`Since Arthur`、`Even`、`Its`、`Hatchery Basin`）不会再被当成人物主体写入画面。
- 当前质检策略：分镜修复后会生成内部质量报告，并把摘要追加到 notes；质检会检查 prompt 固定标签、阅读行一致性等问题。阅读行一致性检查会忽略 `【停顿0.4s】`、`【停顿0.8s】` 这类口型控制标记，避免把正确停顿误报为原文不一致。硬幻觉重写、局部视觉清洗和提示词质量补全已按严重程度分层：空白背景、标题词误识别、无证据医院/急救室/手术台等 fatal 问题才在导演批注中标为“可靠性修复镜头”；局部无证据人物、泛称人物、局部无证据场景词优先清洗并保留原主体动作；仅缺光源、空间层次、焦距/景深等质量项时只补全提示词，不标记为可靠性修复。
